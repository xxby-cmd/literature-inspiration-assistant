# 开发与验证

## 工程边界

Windows 10/11 x64、Python 3.11+、Node.js 22.18+。Python 核心只使用标准库；前端版本由 `reader/package-lock.json` 锁定。首次构建需要访问官方 npm、Node.js 等下载服务。

这个仓库没有作者的运行数据，也不依赖内部 Sites 项目。`reader` 使用标准 Vite/Vinext 与本地 Cloudflare Worker/D1；Worker 只监听回环地址，私人网关负责登录入口、转发和实例身份校验。不要将 Worker 端口直接暴露到公网。

正式数据、演示数据、凭据、模型登录、文章和日志放在源码外。更换源码目录后重新运行安装器更新路径；迁移到另一 Windows 用户时需重新绑定加密凭据。一个源码目录可以分别安装正式和演示数据，但构建或更新前应停止该目录的所有实例；不要并发更新同一份源码。

## 本地验证

在仓库根目录打开 PowerShell：

```powershell
python -X utf8 -m unittest discover -s tests -p "test_*.py"
cd reader
npm ci
npm test
npm run typecheck
npm run build
cd ..
python -X utf8 launch.py install --demo --yes --no-browser --home "$env:TEMP\literature-clean-demo"
python -X utf8 scripts/smoke.py --home "$env:TEMP\literature-clean-demo"
```

演示路径必须是专用目录。`smoke.py` 会启动、停止和修改该演示实例的端口，拒绝操作正式实例；测试结束会停止演示。它检查五篇示例、拒绝错误实例访问、旧端口被其他程序占用时自动换端口、重启后的数据和历史一致。不会使用真实模型或发送微信。CI在Windows上执行相同路径。

常规开发可运行 `npm run dev`，但它不是正式安装入口；正式运行需要安装器建立数据库、私人入口和实例标识。源码修改后重新安装会按构建指纹更新；无需手动清理构建目录。正在生成文章时会等待安全退出，默认120秒，必要时添加 `--wait 900`。

## 发布验收覆盖

- Python 回归覆盖时钟、队列、重试、微信协议、入口保护、模型认证隔离及接入中断恢复。
- Node 回归覆盖排版安全、阅读缓存、反馈幂等、独立文献分组、书架和主题历史；包括65条主题历史的排序、重复读取一致性与不触发新任务。
- Windows本机实际执行过锁定依赖安装、类型检查、构建和独立演示安装；运行中的回归数量以CI日志为准。
- 新用户的ChatGPT登录、PushPlus实名、扫码、网络白名单及手机实际接收，需要本人完成。演示安装不能替代这些外部账号的端到端确认。
- 没有为了测试而卸载宿主Python、清空个人登录或购买服务；缺少Python的winget引导属于代码检查范围，不冒称在空白Windows重装系统上完成全部验证。
- 独立官方Codex CLI自动安装和所需参数能力检查已实际通过。本轮宿主网络无法解析Node.js下载域名，便携Node下载分支没有完成实网验收；清洁部署使用本机已安装的合格Node，未使用旧前端依赖或构建结果。

## 提交前

不要提交本机数据、访问入口码、auth.json、DPAPI文件、日志、论文全文或私人截图。`.gitignore`只是第一层保护，仍须核对待提交文件。新增文献来源需保留证据范围和许可边界；检索结果不保证覆盖网上所有文献，也不能证明一个课题从未被研究。

提交问题时只提供去除个人内容后的错误摘要、系统版本和操作步骤。不要上传数据目录。
